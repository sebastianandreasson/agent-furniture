# Web studio architecture

The browser is a consumer of generated geometry, not another model authoring surface.

```text
designs/*.json + src/querycad/**/*.py
                  │
                  ▼
  uv run querycad preview (watch + build)
                  │
                  ▼
build/<design>/{GLB,STEP,STL,SVG,CSV,manifest}
build/catalog.json
                  │
                  ▼
        Vite publicDir: ../build
                  │
                  ▼
 React Three Fiber + Drei editor
```

`catalog.json` is regenerated by a normal build and contains a SHA-256-derived GLB revision. The UI
polls it every second. A changed revision gives `useGLTF` a new URL while the persisted placement
remains keyed by the stable build directory ID. Old revision URLs are cleared from the GLTF loader
cache after the replacement commits, keeping repeated modeling iterations from retaining stale
assets.

The Python preview loop debounces editor save sequences, then invokes the build in a fresh Python
process so changes to imported model modules are always picked up. Failed builds do not update the
catalog; the last good geometry therefore stays available while the console reports the validation,
syntax, or export error. The same preview command starts Vite when needed and reuses an existing
QueryCAD studio on the requested port. A per-design process lock prevents competing watchers.

The entryway bench example uses Python-first parameters: its JSON `parameters` object is empty, so
edits to `EntrywayBenchSpec` flow directly into the build. JSON remains the higher-precedence layer
when a design intentionally defines an override.

Idle catalog responses are content-deduplicated before entering React state, so polling does not
rerender the Three.js scene. A changed revision is applied as a React transition: the old GLB remains
visible until the replacement is loaded, then the scene swaps atomically. The full-screen loader is
not used because it would blank the viewport during every valid rebuild.

The viewer automatically compares the loaded GLB bounding box to the manifest dimensions. This
handles the CadQuery/OpenCascade glTF axis boundary and prevents accidental unit drift. User placement
scale is never exposed or persisted.

The Studio toolbar's Helpers toggle controls the transform controls, orientation gizmo, and selected
object bounding box together. Helpers are visible by default; the preference is retained locally
without changing model geometry or saved placement coordinates.

The Materials page fetches the selected build's generated manifest using the same catalog revision.
It groups occurrences by material, displays the exact CAD color, totals finished-solid volume, and
lists every stable part number with quantity and stock dimensions. If the model publishes joinery,
the same manifest also supplies fastener specifications and quantities, joint groups, and drilling
operations. It still does not estimate purchase stock, waste, upholstery allowances, structural
capacity, or fabrication tolerances.

The same page renders proportional stock-face schematics for every unique part. Each diagram shows
its part number, assembly quantity, material, dimensions, numbered drill-centre crosshairs, and
per-operation coordinates. Multiple marked faces are shown when a part needs drilling from more than
one orientation. The hardware roll-up, drill legend, assembly sequence, and qualification notes are
part of the A4 landscape print/PDF output. It is a dimensioned reference, not a one-to-one template
or CNC toolpath.

On screen, the schematic sits beside a dedicated orbitable GLB preview. Manifest placement names map
each stable part number back to the assembly nodes, so hovering or keyboard-focusing a schematic card
highlights every occurrence of that part while dimming the rest. Hovering a joint row similarly
highlights its drilled source part. The print stylesheet omits the model and keeps only the
fabrication-oriented document.

The React source mirrors these responsibilities instead of concentrating them in the app shell.
`hooks/useBuildCatalog.ts` owns polling and content deduplication; `studio/` owns the editor panels;
and `materials/` owns manifest loading, pure inventory projections, part schematic drawing, joinery
schedules, and assembly highlighting. `App.tsx` only selects the current catalog design and composes
the active page. Manifest parsing remains one deep, generic adapter in `lib/manifest.ts`, so every UI
feature receives the same validated artifact contract.

The current online splat is a CORS-enabled sample hosted on GitHub. It proves mixed mesh/splat
rendering and streaming, but it is deliberately labelled uncalibrated. Replace it with a captured
apartment asset and a calibrated `ApartmentRoot` transform before using visual alignment for planning.
